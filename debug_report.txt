4. Root Cause of Submission Failure
   - `useAuth()` hook reports `user` as null; localStorage/cookies contain no Supabase session entries (`sb-...` keys absent).
   - `handleSubmit` guard (ExpenseForm.tsx lines ~626-638) checks `if (!user?.id)` and aborts before building FormData, leading to authentication error toast.
   - Because submission short-circuits, no data reaches Supabase tables (reimbursements, vendors, items) and no storage upload is attempted for the final attachment (only initial OCR upload occurs).

5. Recommendations
   - Sign in (or stub a valid Supabase session) before testing claim submission so `user.id` is defined.
   - Optionally enhance UX: redirect unauthenticated users to login rather than showing inline error after form completion.
   - After restoring auth, re-test to ensure POST /api/v1/reimbursements executes and verify records appear in Supabase (`reimbursements`, `reimbursement_items`, `reimbursement_attachments`) and file in `receipts-bucket`.
